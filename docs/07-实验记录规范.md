# 07 · 实验记录规范：字段、指标与复盘

> 目的：让一个月的交易变成可分析的数据，而不是一堆回忆。
> 更新日期：2026-10-03。

## 1. 为什么记录是这套打法最重要的部分

100 USDT 大概率会亏光，唯一能留下的资产是**数据**。没有记录，一个月后你只能说"感觉不太行"；有记录，你能算出胜率、赔率和期望值，判断这套打法该升级还是该放弃。

## 2. 逐笔交易日志

字段定义（对应 `journal/trade-log.csv`）：

| 字段 | 说明 |
|:-----|:-----|
| `id` | 递增序号 |
| `opened_at` | 建仓时间 (UTC) |
| `closed_at` | 平仓时间 (UTC) |
| `token_mint` | 代币地址 |
| `symbol` | 代币符号 |
| `entry_reason` | 入场理由（一句话） |
| `checks_passed` | 是否通过全部硬性检查 |
| `score` | 评分卡得分 |
| `size_usdt` | 投入金额 |
| `entry_mcap` | 建仓时市值 |
| `exit_mcap` | 平仓时市值 |
| `exit_reason` | 平仓原因（止损/止盈/逻辑破/流动性抽走） |
| `pnl_usdt` | 盈亏金额 |
| `pnl_pct` | 盈亏比例 |
| `holding_minutes` | 持仓时长（分钟） |
| `notes` | 复盘备注 |

## 3. 记录纪律

- **开仓前**填写：入场理由、检查项、评分、计划止损/止盈位。
- **平仓时**填写：出场原因、盈亏、持仓时长。
- **当天结束**填写每日复盘模板（`journal/daily-template.md`）。
- 宁可写得粗糙，也不能事后补记——事后补记会不自觉美化决策。

## 4. 月末指标

用 `trade-log.csv` 计算：

| 指标 | 公式/说明 |
|:-----|:----------|
| 交易笔数 | 总开仓次数 |
| 胜率 | 盈利笔数 / 总笔数 |
| 平均盈利 | 盈利单的平均 `pnl_pct` |
| 平均亏损 | 亏损单的平均 `pnl_pct` |
| 盈亏比 | 平均盈利 / 平均亏损 |
| 期望值 | 胜率 × 平均盈利 − (1−胜率) × 平均亏损 |
| 最大单笔盈利 | 最高 `pnl_pct` |
| 最大回撤 | 权益曲线峰值到谷值的最大跌幅 |
| 归零笔数 | `pnl_pct = -100` 的笔数 |
| 纪律违反次数 | 每日复盘里统计 |

**核心问题**：期望值是否为正？如果为正，是运气还是规则？如果为负，哪条规则最该改？

**候选级回填指标（自动，M3）**：除了真实交易的 `trade-log.csv`，筛选系统还会对
**所有候选**自动记录市场快照（`market_snapshots` 表），因此可以算出"被 pass /
manual / reject 的币后来分别涨跌如何"。用 `npm run backfill:report` 查看：
追踪数量、胜/负/近归零（≤ −99%）数量、首→末涨跌幅的均值与中位数、最好/最差样本。
这才是判断"筛选规则有没有用"的直接证据——只看真实成交笔数会样本太少。

## 5. 规则迭代方法

1. 把每个归零样本的链上特征拿出来，和当时的评分卡对照。
2. 找出"评分通过了但归零"的样本，看漏掉了哪个维度 → 加进否决清单或调权重。
3. 找出"被否决但大涨"的样本，看是不是规则过严 → 放宽阈值。
4. 每次只改一条规则，记录改动日期和理由，避免同时调参看不出效果。
