# 09 · 路线图与验收：Stage Gate

> 目的：把"想玩的冲动"套进分阶段的门禁，避免一上来就真金白银硬冲。
> 更新日期：2026-10-03。

## 总览

```
G0 准备 ─▶ G1 只读监控 ─▶ G2 纸面/试卖验证 ─▶ G3 挑战执行 ─▶ G4 复盘
(本周)     (1 周内)        (2–3 天)            (1 个月)        (月末)
```

每一关有明确的**进入条件**和**通过标准**，不达标就停在原地，不硬冲下一关。

## G0 · 准备

**目标**：环境与纪律就位，零资金风险。

- 通读 `docs/01–05`。
- 建立 burner 钱包，确认只放 100 USDT。
- 确认交易终端可用，跑通一笔极小额的买卖（熟悉流程，成本计入预算）。
- 下载并填写 `journal/trade-log.csv`。

**通过标准**：钱包就位、流程跑通、文档读完。

## G1 · 只读监控上线

**目标**：预警系统可用，仍然零资金风险。

- 完成 `docs/06` 的 M0–M3。
- 连续运行 ≥ 3 天，观察推送质量。

**通过标准**：

- 新币事件能稳定采集并去重。
- 硬性过滤与评分能正常输出。
- 推送内容可读、误报率可接受。

**注意（2026-10-03）**：新币在发现时没有流动性/持币数据，`freshGraceSec`
宽限期内会降级为 `manual`；若 `pipeline.notifyManual: true`，则每个通过的
安全底线的新币都会推送，可能形成刷屏。观察期的第一件事就是据此决定要不要
关掉 manual 推送（或改为定时汇总）。

## G2 · 纸面 / 小额验证

**目标**：在不动主要资金的前提下验证判断力。

- 用**纸面交易**记录 10–20 个候选的假设入场与结果。
- 或用极小金额（如 0.5 USDT）真实走几笔，验证流程与滑点。

**通过标准**：能说清"如果真做会赚还是亏"，并知道错在哪里。

## G3 · 挑战执行（1 个月）

**目标**：按 `docs/05` 的规则真实执行 100 USDT 挑战。

- 严格执行资金结构、入场、出场规则。
- 每笔记录，每日复盘，每周统计。

**熔断条件**（任一触发即停止交易，进入复盘）：

- 剩余资金跌破下限。
- 单日亏损超过阈值。
- 情绪失控、连续违反纪律。

## G4 · 复盘

**目标**：产出结论，而不是结果。

**必须回答的问题**：

- 真实胜率、平均赔率、期望值？
- 哪条规则有效、哪条无效？
- 归零样本的共同特征是什么？
- 下一版规则怎么改？
- 这套打法值得放大，还是应该放弃？
